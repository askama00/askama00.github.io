Ubuntu安装Docker及使用手册

Docker 是一个开源的容器化平台，它允许开发者将应用及其全部依赖打包到一个可移植的“容器”中，然后发布到任何支持 Docker 的 Linux 机器上运行。用一个不太精确但很直观的比喻：Docker 镜像就像一份“软件安装包”，容器则是安装并运行后的程序实例。与传统虚拟机相比，Docker 容器直接运行在宿主机的内核之上，不需要模拟完整的操作系统，因此启动速度极快、资源占用极低，每个容器之间相互隔离、互不影响。

本文提供一套使用三方镜像源在Ubuntu上安装Docker的方案，因为默认的Docker安装源地址网络不尽如人意，所以我们在安装Docker以及拉取镜像的时候都需要用到三方镜像源。

安装Docker

首先，如果你之前使用 Ubuntu 官方仓库安装过 Docker，也就是通过 apt install docker.io 安装的版本，那么建议先卸载旧包，再添加三方镜像源安装 docker-ce。因为 docker.io 和 docker-ce 是两个不同的包，会提供相同的命令和系统服务，混装容易导致冲突。若你之前已经使用的是 docker-ce，则无需卸载，直接升级即可。

卸载老版本Docker

如果确认需要卸载自己的Docker，那么可以使用如下命令先将老版本的Docker卸载。

sudo apt remove docker docker-engine docker.io containerd runc

卸载之后，我们就要进入下一步导入三方源地址和密钥。

导入三方源地址和密钥

首先，我们先执行如下命令装必要的工具。

sudo apt-get install ca-certificates curl gnupg lsb-release

然后，我们可以导入阿里云的地址和密钥，这样可以确保成功安装Docker，但是作者最近发现阿里云的地址现在下载速度很慢，但是作者暂时没找到好用的别的镜像地址，用户可以自己找一些其他的镜像源使用，比如华为源，使用方式基本是一样的。 我们执行如下命令，导入阿里的证书

sudo curl -fsSL https://mirrors.aliyun.com/docker-ce/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg

没有报错以及提示则导入成功，然后执行如下命令添加阿里云的Docker源到apt源配置中

echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://mirrors.aliyun.com/docker-ce/linux/ubuntu/ $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

同样，没有报错以及提示则导入成功，因为更改了apt源配置，所以要执行update命令刷新apt源

sudo apt update

更新成功之后，执行如下指令安装Docker以及Docker相关便捷组件

sudo apt install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin -y

安装完成之后，我们可以使用如下命令，查看docker版本，如果输出正常则安装成功，如果我们使用的是普通用户，那么执行docker命令的时候需要使用sudo

docker -v

至此Docker已初步安装完成

主要命令说明

Docker 的命令可以粗略分成两类：docker 本体命令，以及 docker compose（多容器编排，已随上面的安装一并装上）。先记住一条主线：镜像（image）是只读模板，容器（container）是镜像运行起来的实例；大多数容器命令都有对应的 docker image ... / docker container ... 长写法，短写法的 docker ps、docker rm 只是别名，功能相同。

1. 镜像相关命令

# 列出本地已有镜像
docker images
# 等价：docker image ls

# 搜索镜像（结果来自配置的镜像源/仓库）
docker search nginx

# 拉取镜像，格式：docker pull 镜像名[:标签]
docker pull nginx
docker pull mysql:8.0        # 不写标签默认 latest，生产建议固定版本号

# 删除本地镜像（容器正在使用时需先删容器）
docker rmi nginx:latest
docker rmi $(docker images -f "dangling=true" -q)   # 清理悬空镜像（<none>）

# 给镜像打标签（常用于推送到自己的仓库前改名）
docker tag nginx:latest registry.example.com/mynginx:1.0

# 保存镜像为 tar 文件 / 从 tar 文件载入（内网环境拷贝镜像很有用）
docker save -o nginx.tar nginx:latest
docker load -i nginx.tar

# 查看镜像分层与大小 / 查看镜像详细信息
docker history nginx:latest
docker inspect nginx:latest

2. 容器相关命令

docker run 是最核心也参数最多的命令，常见参数先记牢：

参数含义
-d后台运行（detached）
--name 名字给容器起名字，否则随机生成
-p 宿主机端口:容器端口端口映射，如 -p 8080:80
-v 宿主机路径:容器路径目录/数据卷挂载
-e KEY=VALUE注入环境变量（数据库密码等）
--restart unless-stopped开机自启 + 异常退出自动拉起
--rm容器停止后自动删除（调试用，别用于要留数据的容器）
-it交互式 + 伪终端，常配合 /bin/bash 进容器

常用操作：

# 运行一个 nginx 并映射端口
docker run -d --name mynginx -p 8080:80 --restart unless-stopped nginx

# 运行 MySQL，设置 root 密码并挂载数据目录
docker run -d --name mysql8 \
  -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD=your_strong_password \
  -v /srv/mysql/data:/var/lib/mysql \
  --restart unless-stopped mysql:8.0

# 查看正在运行的容器 / 查看全部（含已退出）
docker ps
docker ps -a

# 启动 / 停止 / 重启 / 强制杀掉容器
docker start mynginx
docker stop mynginx
docker restart mynginx
docker kill mynginx

# 进入正在运行的容器（退出用 exit；不要用 attach 跑服务容器，容易误停）
docker exec -it mynginx /bin/bash
docker exec -it mysql8 mysql -uroot -p

# 查看日志（排障第一手段）：-f 持续跟踪，--tail 看最后 N 行
docker logs -f --tail 100 mysql8

# 查看容器资源占用 / 容器内进程 / 完整配置
docker stats
docker top mynginx
docker inspect mynginx

# 容器与宿主机互拷文件
docker cp mynginx:/etc/nginx/nginx.conf ./
docker cp ./nginx.conf mynginx:/etc/nginx/nginx.conf

# 删除已停止的容器 / 删除容器（运行中需加 -f）
docker rm mynginx
docker rm -f mynginx

# 批量清理：删除所有已停止的容器、悬空镜像、未用网络、未用构建缓存
docker container prune
docker system prune        # 加 -a 会连没被使用的镜像一起删，谨慎

3. Docker Compose（多容器编排）

适合一次启动一组互相依赖的容器（如 Web + 数据库 + 缓存）。在项目目录新建 docker-compose.yml：

services:
  web:
    image: nginx:latest
    ports:
      - "8080:80"
    volumes:
      - ./html:/usr/share/nginx/html:ro
    depends_on:
      - db
    restart: unless-stopped

  db:
    image: mysql:8.0
    environment:
      MYSQL_ROOT_PASSWORD: your_strong_password
      MYSQL_DATABASE: appdb
    volumes:
      - dbdata:/var/lib/mysql
    restart: unless-stopped

volumes:
  dbdata:

对应命令：

docker compose up -d        # 后台启动整套服务（首次会自动构建/拉取）
docker compose ps           # 查看服务状态
docker compose logs -f db   # 跟踪某个服务的日志
docker compose exec db bash # 进入某个服务
docker compose restart      # 重启
docker compose down         # 停止并删除容器和网络（数据卷默认保留）
docker compose down -v      # 连数据卷一起删（慎用）
docker compose pull && docker compose up -d   # 升级镜像后平滑重启

配置镜像加速（拉取镜像）

安装源换成三方镜像只能解决“装 Docker”慢的问题，拉取 Docker Hub 上的镜像慢，需要配置 registry-mirrors。编辑（不存在则新建）：

sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json <<-'EOF'
{
  "registry-mirrors": [
    "https://你的专属加速地址.mirror.aliyuncs.com"
  ]
}
EOF

sudo systemctl daemon-reload
sudo systemctl restart docker
docker info | grep -A 5 "Registry Mirrors"   # 验证是否生效

需要说明的是：2024 年中以后，国内大量公共 Docker Hub 加速地址陆续关停或限制，可用性变化非常快。相对稳妥的做法是登录阿里云容器镜像服务控制台，使用“个人专属加速器地址”（每人不同、需登录获取）；其余公开地址使用前请先自行验证是否仍可用。镜像拉不动的另一个兜底思路是：找一台网络正常的机器 docker pull 后 docker save，再拷到目标机 docker load。

免 sudo 使用 Docker

sudo usermod -aG docker $USER
newgrp docker        # 让组生效；或者直接注销重新登录
docker ps            # 不再加 sudo 能执行即成功

再次提醒：docker 组等价于 root 权限，不要给不可信用户加组；也不要把 /var/run/docker.sock 挂载进容器（等于把宿主机 root 交给容器）。

常用场景速查

# 一键跑个临时环境用完即删（演示、抓包排查都很顺手）
docker run --rm -it ubuntu:22.04 bash

# 查看容器占用的磁盘，定位哪个镜像/容器最吃空间
docker system df
docker system df -v

常见问题（FAQ）

  1. Cannot connect to the Docker daemon：一是 Docker 没启动，sudo systemctl enable --now docker；二是当前用户不在 docker 组或没重新登录。
  2. 容器一启动就退出：docker logs 容器名 看报错；多半是启动命令结束（前台程序跑完）或配置/环境变量错误。
  3. 端口被占用：sudo ss -lntup | grep 端口号 找到占用进程；改宿主机侧端口即可，-p 8081:80。
  4. 磁盘被 Docker 吃满：docker system df 定位，确认无用后 docker system prune 系列命令清理；生产环境建议定期任务清理悬空镜像与停止的容器。
  5. 容器里时间不对：挂载宿主机时区文件 -v /etc/localtime:/etc/localtime:ro。
  6. 改了 daemon.json 后 Docker 起不来：sudo dockerd 前台运行看具体报错，多半是 JSON 多了逗号或写错字段。

安全与维护建议

  • 镜像固定版本号，慎用 latest；优先使用官方镜像（Verified Publisher / Official）。
  • 不要把密码写进仓库，敏感信息用环境变量注入或 secrets 管理。
  • 需要持久化的数据一律挂卷（-v），不要把重要数据放在容器可写层里。
  • 定期更新宿主机内核与 Docker，并对外暴露端口前确认防火墙/安全组策略。
  • 给关键数据卷做备份：停机后打包数据目录，或使用 docker run --rm -v 数据卷:/data -v $PWD:/backup busybox tar czf /backup/data.tar.gz -C /data . 之类的方式导出。

至此，你已经可以在 Ubuntu 上完成 Docker 的安装、镜像加速、免 sudo 配置、日常启停与排障。后续进阶方向建议按顺序了解：Dockerfile 构建镜像、多阶段构建减小体积、Docker Compose 的 build 与 networks，以及 Docker Swarm / Kubernetes 做编排。
